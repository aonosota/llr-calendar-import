# LLR Calendar Import 要件定義書(v0.3.1)

作成日: 2026-11-04 / v0.3 にユーザー確認済みの決定事項(下記 0.1)を追記した版。
**0.1 の決定事項は本文より優先する。**

## 0.1 決定事項(2026-11-04 ユーザー確認済み)

1. **見出し書式**: デイリーノートのセクション見出しは `## 朝` のようにラベルのみ。
   照合は「見出しテキストを trim して完全一致」が既定、設定で部分一致に切替可。見出しレベル(#の数)は問わない。
2. **LLR 行の書式**: GitHub README 形式 `- [ ] HH:mm タスク名 (見積もり)` を採用。行生成は `src/llr/` に隔離。
3. **日付変更時刻(dayBoundary, 既定 04:00)を新設**。3.5.2 の「最初のセクションより前の予定」設定は廃止し、以下で置き換える:
   - 論理日付 D のノートに入る予定 = 開始が `[D@境界, D+1@境界)` の予定
   - D の 00:00〜境界前の予定は D−1 のノートに入る(D のノートには入らない)
   - 境界〜最初のセクション開始前 → **最初のセクション**
   - D+1 の 00:00〜境界前 → **最後のセクション**(全セクション開始より後とみなす)
   - セクション割り当て・セクション内の並びは「境界からの経過分」で比較する(`01:00` は `23:00` より後)。既存行の `HH:mm` も同じ基準
   - 「今日の予定を挿入」の「今日」は境界で判定(境界 04:00 で 11/5 01:30 に実行 → 11/4)
   - 重複判定キーは UID + 開始日時(日付込み、ISO UTC)のまま
4. **終日予定**: 既定スキップ。設定で含める場合はフォールバック見出しの下に時刻なしで入れる(`- [ ] タイトル`)。
5. **ical.js (MPL-2.0)** を採用。改変せず同梱し NOTICE.md に記載。
6. 日付またぎの見積もりは「開始日の 24:00 まで」に丸める(v0.3 3.3 のまま)。

---

## 1. 目的
カレンダーの予定を読み取り、LLR(Live Life Recording)の記法で、
デイリーノートの**時間帯セクションごとに振り分けて**挿入する。

```
## 朝
- [ ] 09:00 定例ミーティング (30m)
## 午後
- [ ] 13:00 歯医者 (60m)
- [ ] 15:30 打ち合わせ (45m)
```

## 2. 位置づけとスコープ

### 2.1 方針
- **一方向**(カレンダー → Obsidian)。カレンダー側へは何も書き込まない
- **LLR 本体とは独立した別プラグイン**。LLR のコードには依存せず、LLR 記法の行を出力する
- 初期リリースの取得方式は **ICS URL**(認証不要)。**将来 OAuth 方式を追加できる**設計にする(7章)
- 取り込みは**手動コマンドのみ**

### 2.2 スコープ外(初期リリース)
- OAuth、カレンダーへの書き込み、双方向同期
- 自動挿入(デイリーノート作成時・起動時など)
- 挿入済みの行の更新・削除(既存の行は一切書き換えない)
- CalDAV、アカウントログインが必要なカレンダー
- LLR のルーチン・サマリー機能との連動

## 3. 機能要件

### 3.1 コマンド
| コマンド | 動作 |
|---|---|
| **今日の予定を挿入** | 今日(境界で判定)の予定を、今日のデイリーノートに挿入する |
| **日付を指定して予定を挿入** | 日付を入力し、その日のデイリーノートに挿入する。ノートが無い場合は作成確認を出す |

- 実行結果は通知で表示する(例: 「5 件を挿入(朝 2、午後 3)、1 件は挿入済みのためスキップ」)

### 3.2 ICS の取得とパース
- 取得: Obsidian の `requestUrl`(CORS を回避でき、モバイルでも動く)
- 複数の URL を順に処理する。一部が失敗しても他は続行し、失敗を通知する
- 対象範囲(0.1-3 の窓)の予定を抽出する:
  - 通常の予定(日時指定の `DTSTART` / `DTEND` / `DURATION`)
  - **繰り返し予定**(`RRULE`/`RDATE`)の展開。例外日(`EXDATE`)と、変更された回(`RECURRENCE-ID`)を反映
  - タイムゾーン(`TZID` 付き、UTC の `Z` 付き、フローティング)をローカル時刻に変換
  - `STATUS:CANCELLED` は除外。終日予定は既定で除外(除外は呼び出し側で行う)
- パーサーは ical.js

### 3.3 LLR 行への変換
```
- [ ] HH:mm タスク名 (見積もり)
```
| 項目 | 変換ルール |
|---|---|
| 時刻 | 予定の開始時刻(ローカル時刻、24 時間表記 `HH:mm`) |
| タスク名 | 予定のタイトル(3.4 の整形を適用) |
| 見積もり | `DTEND − DTSTART`。既定の表記は `Nm`(`30m`, `90m`)。設定で `1.5h` 形式に変更可 |
| 終了時刻なし | 「既定の長さ」設定(初期値 30 分) |
| 日付またぎ | 開始日の行として扱い、見積もりは開始日の 24:00 までに丸める |

### 3.4 タイトルの整形(LLR の解析を壊さないため)
- 改行は半角スペースにする
- `HH:mm` 形式の時刻(例: `Meeting 10:00`)は、誤解析を避けるため別の表記に置換する(例: `10:00` → `10∶00`(U+2236)。方式は実装で一意に決め、テストで固定)
- 行末の `(30)` `(1h)` のような括弧つき数字は見積もりと誤認されるため、全角括弧に置換する
- `@done`、`@MMDD` など LLR のマーカーに見える文字列は無害化する
- 前後の空白を除去する。空のタイトルは「(無題)」にする
- 任意の接頭辞(例: カレンダー名)を付けられる(設定)

### 3.5 セクションへの振り分け

#### 3.5.1 セクション定義
- 設定に「セクション定義」を持つ。1 件 = {開始時刻, 見出しラベル}
- 初期リリースは手動入力。LLR 設定の取り込みは任意機能(後回し)

#### 3.5.2 割り当てルール(0.1-3 で更新)
- 境界からの経過分 t について、「開始(境界からの経過分)が t 以下のセクションのうち最も遅いもの」。該当なし(境界〜最初のセクション前)は最初のセクション
- 開始時刻は一意

#### 3.5.3 セクション内の挿入位置
- 対象セクション(見出しの直下、次の同レベル以上の見出しの直前まで)の中で、**既存の行は並べ替えない**。新しい行は:
  - セクション内の既存タスク行のうち、行頭に `HH:mm` を持つ最初の行で、その時刻が新しい行の時刻より**遅い**(境界基準)ものの直前
  - 該当が無ければ、セクション内の最後のリスト行(タスク行・メモ行)の直後
  - リスト行が無ければ、見出しの直下
- 同じ時刻の予定が複数ある場合は、入力順(ICS 内の順)を保つ
- セクション内のメモ(リスト以外の文章)を壊さない

#### 3.5.4 セクションが見つからない場合
- セクション見出しを**新規作成しない**
- フォールバック見出し(既定 `## Calendar`)の下に追記する。無ければノート末尾に作る
- 通知で件数を知らせる。設定画面に「LLR の Insert Routine を先に実行すると見出しが揃う」旨を記載

### 3.6 重複防止と変更への対応
- 判定キー: 「予定の UID + 開始日時」。記録先: data.json(ノート本文に ID を書かない)
- フォールバック: 記録が無い場合、ノート全体で「開始時刻 + タイトル」が一致するタスク行があればスキップ(チェック状態 `[ ]` `[/]` `[x]` 問わず、時刻の後ろがタイトルで始まれば一致)
- 同じ UID でも開始日時またはタイトルが記録と異なれば新規扱いで追記し、「changed」として通知
- 既存の行は一切書き換えない

### 3.7 フィルタ
- 除外キーワード(タイトルに含まれていたらスキップ。複数、大文字小文字無視)
- 辞退(`PARTSTAT=DECLINED`)をスキップ(既定オン。判定に「自分のメールアドレス」)
- 仮承諾(STATUS:TENTATIVE または自分の PARTSTAT=TENTATIVE)の接頭辞(設定、空なら付けない)

## 4. 設定項目
`src/types.ts` の `PluginSettings` / `DEFAULT_SETTINGS` を正とする。

## 5. 非機能要件
| 項目 | 内容 |
|---|---|
| セキュリティ | ICS の非公開 URL はパスワード相当。SecretStorage が使えれば優先、無ければ data.json。ログ・通知・エラーに URL を出さない |
| 同期との相性 | data.json は同期されうる旨を設定画面に注意書き |
| プライバシー | 取得は指定 URL のみ。テレメトリなし |
| 性能 | 数十件で数秒以内 |
| 失敗時の安全性 | 取得・パース失敗時はノートを変更しない。一部 URL の失敗は通知して継続 |
| プラットフォーム | デスクトップ・モバイル両対応(`isDesktopOnly: false`)。Node API を使わない |
| 保守性 | ICS 展開・行生成・セクション割り当て・挿入位置は Obsidian 非依存の純関数 + vitest |
| 多言語 | 日本語 / 英語 |
| 最小 Obsidian | 1.8.7(当初 1.7.2 だったが、公式 `getLanguage()` を使うため 2026-11-06 に引き上げ) |

## 6. モジュール構成
- `src/types.ts`, `src/time.ts` — 共有契約(凍結)
- `src/source/ics/` — ICS 取得・パース・展開(`CalendarSource` 実装)
- `src/llr/` — LLR 行の生成
- `src/section/` — セクション定義・割り当て・見出し探索
- `src/insert/` — 挿入位置の決定、重複判定
- `src/ui/` + `src/main.ts` — コマンド、モーダル、設定タブ、通知、data.json

## 7. 将来拡張: OAuth
`CalendarSource` の背後に置く。挿入ロジックは取得方式を知らない。判定キーは共通。

## 8. 受け入れ基準
1. 「今日の予定を挿入」で `- [ ] HH:mm タイトル (Nm)` が開始時刻の属するセクションに追記される
2. 再実行で重複しない
3. LLR で開始・完了した行も、再実行で書き換えられず重複もしない
4. 既存行の並びは不変。新しい行はセクション内の時刻順の位置に入る
5. セクション見出しが無い場合フォールバックに入り通知される。セクション見出しは作らない
6. 境界〜最初のセクション前 → 最初のセクション、翌日 0:00〜境界前 → 最後のセクション、当日 0:00〜境界前 → 前日のノート
7. 時刻変更後の再実行で新しい行が追記され、古い行は残る
8. 繰り返し予定が正しく展開される(例外日・変更回を含む)
9. UTC・TZID・フローティングがローカル時刻に正しく変換される
10. キャンセルは挿入されない。終日は既定で挿入されない
11. タイトルの `10:00` や `(30)` を LLR が誤認しない
12. 一部 URL 失敗でも他は挿入され、失敗が通知される
13. 取得失敗時ノート不変。通知・ログに URL が出ない
14. モバイルでも動作
